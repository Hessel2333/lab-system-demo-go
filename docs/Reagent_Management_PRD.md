# 试剂管理系统 (LIMS-Reagent) 需求与架构文档

## 1. 模块概述
本模块旨在为实验室提供一个完整闭环的、细化到“单瓶瓶身（一物一码）”级别的试剂全生命周期管理系统。
系统涵盖了从**试剂申购 -> 领导/采购审批下单 -> 供应商发货 -> 前台分拣暂存（赋码） -> 领用入库（具体实验室/安全柜） -> 领用消耗 -> 空瓶核销**的全流程业务管理。

通过结合 AI 解析技术、角色权限控制（RBAC）以及 BPM 流程跟踪，大幅降低了实验人员的录入成本，增加了物资管理的透明度和合规性（特别是针对管制试剂的双人双锁等要求）。

---

## 2. 核心角色与业务流转 (Role-Based Workflows)

系统主要涉及三种角色视角：研发人员（Researcher）、采购/库管人员（Procurement）、团队主管（Leader）。

### 2.1 研发人员 (Researcher / 用户)
*   **试剂申购**：
    *   可以通过 **AI 助手**输入自然语言（如“我要两瓶纯度99%的分析纯丙酮”）一键提取化学品名称、CAS 号、规格等信息。
    *   可以通过历史记录、常用试剂清单进行**一键快速填充**。
*   **扫码自取入库**：当采购人员到货并在分拣区生成二维码贴纸后，研发扫码将其转移至最终的实验室位置（如 `E309`, `F103`）。
*   **试剂消耗**：实验过程中扫码使用剩余量，最终耗尽时进行**空瓶核销**，状态变更为 `已耗尽`。
*   **我的台账**：查看由自己发出的申购单进度。

### 2.2 采购人员 (Procurement)
*   **采购任务池审核**：对所有汇总的申购需求进行“**审批并下单采购**”，使得请求状态变更为 `采购中`。
*   **到货核销与赋码**：供应商送货至实验室前台/分拣区时，点击“**确认到货并生成条码**”。
    *   此动作会为每一瓶物理试剂生成全局唯一标识符（UUID），状态标记为 `已到货`，临时存放在 `分拣区(临时区)`。
*   **全库台账监管**：可以查看整个实验室各房间、各人员名下的试剂存量和状态。

### 2.3 团队主管 (Leader)
*   **数据宏观监控**：通过“概览仪表盘”实时掌控资金消耗、高频试剂排行、低库存告警以及管制试剂的安全流向等核心指标。

## 3. 业务状态机 (State Machine)

### 3.1 申购单据状态 (ReagentRequest)
-   `待提交` (Draft)
-   `待处理` (Pending) -> 研发提交需求。
-   `采购中` (Purchasing) -> 采购点击【审批并下单】。
-   `已入库` (Fulfilled) -> 当该订单对应的所有物理试剂被成功分发，生命周期结束。

### 3.2 物理试剂单瓶状态 (ReagentItem)
-   `已到货` (Arrived) -> 采购确认到货，存放在 `分拣区(临时区)`，等待认领。
-   `在库` (InStorage) -> 研发/库管将其移入最终实验房间（如 `E309`, `E307`, `F103`）。
-   `已耗尽` (Used) -> 试剂使用完毕，进行空瓶销户。
-   `已过期` (Expired) -> 超过保质期（系统自动标记）。

## 4. UI 页面架构 (Frontend Layout)

### 4.1 概览仪表盘 (Dashboard)
-   **顶部核心指标卡片**：试剂库存总数 (在库/已到货)、待处理的申购任务数、近7日申请趋势 (图表)、低库存告警数。
-   **系统动态墙**：实时滚动显示系统内的日志（如谁在何时申购了什么、谁扫码入库了某瓶试剂）。

### 4.2 试剂申购向导 (Request Wizard)
-   **左侧：主表单区**
    -   顶部选项卡切分：`AI 智能识别录入` vs `人工精准填报`。
    -   AI 解析结果支持用户手动二次校验和修改。
-   **右侧：快速填充区 (Quick-Fill Sidebar)**
    -   两列垂直排布：【推荐/常用试剂】与【最近我的申购】。
    -   提供一键填充功能，避免遮挡主视图，提升操作效率。

### 4.3 库房台账与采购任务池 (Inventory & Request Pools)
-   **BPM进度追踪**：列表中的每一行都有【查看进度】按钮。点击弹出完整的垂直时间轴，高亮展示当前环节节点（提交申请 -> 采购审批 -> 物流与到货 -> 扫码入库）。
-   **数据列表**：支持全局模糊搜索（CAS、名称、UUID、位置等）、包含“申购人”溯源溯责。

### 4.4 手持端扫码模拟器 (Scanner Simulator)
-   模拟接入外部扫码枪。输入 UUID 点击查询后，弹出该试剂的交互卡片。
-   带有快捷操作栏：如果是在分拣区，提供快捷房号选择（`E309`, `F103` 等）；如果是已经在库，提供一键核销大红按钮。

## 5. 数据模型设计 (Backend Data Model)

系统采取了“字典与实例分离”的底层架构模式，将同一款试剂（基于 CAS 号）的静态属性和具体每一瓶的动态属性分表管理：

1.  **ReagentCatalog (试剂基础目录/字典表)**
    -   核心字段：`CASNumber`(CAS号), `Name`(名称), `Category`(分类:生化/无机等), `IsControlled`(是否管制), `Storage`(建议默认存放环境:如防爆柜), `AlertThreshold`(库存预警线), `Unit`(单位: 500ml/500g)。
2.  **ReagentRequest (试剂申购单/流转采购单)**
    -   核心字段：`RequestorID`(申购人外键), `ReagentCatalogID`(关联字典), `Quantity`(需求瓶数), `Status`(采购状态), `Remarks`。
3.  **ReagentItem (单瓶物理实体表)**
    -   **关键设计**：每瓶唯一的 `UUID` (即粘贴在瓶身的系统条码)。
    -   核心字段：`ReagentRequestID`(溯源属于哪个申购单), `Status`(在库状态:已到货/在库/耗尽), `Location`(实时物理储位: 如 E309), `Capacity`(初装容量), `RemainingVolume`(当前剩余容量), `ExpiryDate`(过期时间), `BatchNumber`(批次号)。
4.  **ReagentLog (操作日志表)**
    -   核心日志链路：每一记扫码动作（入库、领用、核销）都会自动插入到该表中。
    -   核心字段：`UserID`(操作者), `ReagentItemID`(操作对象), `Action`(动作类型:入库登记/空瓶核销), `Quantity`(变更量)。
